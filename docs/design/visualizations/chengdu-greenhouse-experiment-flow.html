01 / Overview

先看一遍完整闭环

研究流程分成七层。任何算法的“好成绩”都必须沿这条链路追溯到数据、模型、实验协议和冻结测试。

1. 数据接入传感器、SQL 控制日志、设备参数、ERA5、作物样本
2. 清洗对齐单位统一、质量标记、小时聚合、控制状态重建
3. 模型建立ChengduPhysics、灰箱残差、Vanthoor 作物模型
4. Gym 封装状态 → 控制动作 → 动力学递推 → 奖励
5. 算法训练Baseline、PID、MPC、PPO、SAC
6. 冻结评估训练调参、验证选型、测试只打开一次
7. 论文结论多指标比较、置信区间、局限与生产门

状态输入

室内温湿度、室外温湿度、辐射、风速、时间周期特征、当前控制量和作物状态。

动作输出

热幕、通风、补光、外遮阳四个可控量；为兼容模型保留六维向量，但加热和 CO2 固定为 0。

奖励目标

最小化温湿度偏差和越界，同时抑制用灯、动作幅值及频繁切换。Reward 越高越好，理论上限为 0。

03 / Models

模型层：控制器面对的“虚拟温室”

预测模型与控制算法不是一回事。模型回答“动作之后环境如何变化”，控制器回答“现在应该采取什么动作”。

环境动力学

ChengduPhysics V4

基于能量与湿量平衡描述温室温湿度递推，使用室外天气、通风、风机、遮阳和热幕等输入。

输入 → 输出 → 验证
输入天气、控制、上一步状态
输出下一步温度与 RH
验证1/6/24/72 h 多步误差
状态物理可解释但系统偏差明显
当前最佳研究模型

V4 + Ridge 灰箱残差

物理模型先给预测，Ridge 只学习残差；周期与辐射交互特征修正系统偏差，不读取未来室内真值。

模拟光合、碳水缓冲、叶茎果分配、呼吸、修剪和果实采收通量，输出站立生物量与仿真产量。

独立预测分支

PINN

用物理约束正则化神经网络，学习环境状态转移。当前首先作为预测器评价，不直接放进控制器 Reward 排名。

独立预测分支

Transformer

利用时间窗口建模长程依赖，适合多变量序列预测。需要严格限制输入窗口，避免把预测时刻之后的观测带入模型。

04 / Gym Loop

Gym 闭环每 15 分钟发生什么

一轮 120 天生长季约有 11,520 个控制步。每一步都执行完全相同的状态、动作、模型和奖励接口。

① Observation 状态

  • 室内温度、相对湿度
  • 室外温湿度、辐射、风速
  • 当前动作与时间周期
  • 可选作物状态和天气预报
→

② Controller 动作

  • uThScr 热幕
  • uVent 通风
  • uLamp 补光
  • uBlScr 外遮阳
  • uBoil=uCO2=0
→

③ Model + Reward

  • 动力学积分到下一状态
  • 计算温湿度偏差与越界
  • 计算照明、动作与切换代价
  • 返回 reward 与终止标记
reward = -(温度偏差 + 湿度偏差 + 越界惩罚 + 补光代价 + 动作幅值 + 动作变化)

所有控制器使用同一个动作适配器、裁剪范围、变化速率限制和奖励函数。否则 Reward 不具备可比性。

05 / Controllers

五种常见算法怎样参与同一场比赛

点击算法名称可高亮当前历史 paper profile 对比行。该表证明流程完整，不代表真实大棚部署效果。

Baseline

基于温度、湿度和昼夜规则的确定性控制器。它是最低复杂度参考，不是“随机算法”。

PID

根据设定值误差的比例、积分、微分项连续调整通风等动作。参数只允许在验证集选择。

MPC

使用环境预测模型向前模拟多个候选动作序列，每一步只执行最优序列的第一个动作，再滚动优化。

PPO

On-policy 策略梯度方法，通过限制新旧策略变化提高训练稳定性；需要多种子报告波动。

SAC

Off-policy 最大熵强化学习，兼顾累计奖励与策略探索，适合连续动作空间。

公平性约束

同一测试天气、初始状态、动作上限、Reward 和采样步长；PID/MPC 调参和 PPO/SAC 选 checkpoint 都不能看测试集。

06 / Protocol

完整实验协议：从冒烟测试到论文表格

“跑通”与“可发表”是两个等级。前者检查软件链路，后者要求固定协议、多随机种子、完整产物与冻结测试。

STEP 1预检数据哈希、时间间隔、非有限值、动作维度、固定控制量
STEP 2Smoke五算法短预算跑通训练、保存、加载、评估和报告
STEP 3Train / Tune训练 PID/MPC/PPO/SAC；只用训练和验证数据
STEP 4Freeze / Test冻结配置、代码、模型哈希；一次性运行独立测试集
STEP 5Aggregate每步轨迹 → 每回合指标 → 多种子均值、标准差和 CI

控制算法选择规则

  • Baseline：固定规则，无训练
  • PID/MPC：验证集网格选择参数
  • PPO/SAC：每个种子用验证 Reward 选 checkpoint
  • 允许报告最优种子时，必须同时保留全部种子统计，并清楚标注选择规则

每次运行必须保存

  • 解析后的完整配置和随机种子
  • 训练元数据、checkpoint、参数搜索记录
  • 逐步状态、动作、Reward 分项和时钟时间
  • 聚合 CSV/JSON、图、manifest 和文件哈希

失败条件

  • 状态或 Reward 出现 NaN/Inf
  • 加热或 CO2 非零
  • 测试天气进入训练或调参
  • 缺失种子却标记 paper-ready
  • 不同算法使用不同 Reward 或动作约束

统计报告

  • RL 至少五个独立随机种子
  • 报告 mean、std、median、95% bootstrap CI
  • 固定单一天气窗口的种子波动不等于天气泛化
  • 最终应按六个独立生长季进行配对比较
07 / Metrics

评价指标不止 Reward，也包括产量与可信度

点击类别筛选指标。论文主表至少覆盖累计 Reward、环境舒适、控制代价、产量和统计稳定性。

Reward

每步奖励之和；越高越好。必须同时报告分项，否则无法判断是舒适性改善还是控制代价变化。

MAE

平均绝对误差，单位直观。温度用 °C，湿度用 %RH；既用于目标跟踪也用于预测模型误差。

RMSE

均方根误差，对少数大误差更敏感；与 MAE 一起报告可识别极端失控。

舒适区

温度/RH 越界小时、各自舒适率和联合舒适率。联合舒适率要求两项同时达标。

控制代价

动作幅值、累计执行强度、补光时长、动作总变差、切换次数和每步计算时间。

产量

fresh_yield_kg_m2 与有限季生产代理。当前是模型输出，不能冒充成都真实采收。

稳定性

多种子 mean/std/median/95% CI；多生长季还应报告逐季差异和配对统计检验。

多步预测

1/6/24/72 h MAE、区间覆盖率、区间宽度、残差自相关和物理边界违规。

作物可信度

站立果/叶/茎 WMAPE、花序 WMAPE、干鲜比敏感性，以及独立采收序列上的累计产量误差。

当前证据怎样落到结论

研究对比：可用

V4 Grey-box 是当前最佳气候预测模型

在冻结测试上明显改善纯 V4，并在 72 h 温度和 RH 两项上优于 Persistence。可用于论文中的混合模型对比和后续 MPC 研究。

生产控制：暂缓

NO_GO_PRODUCTION

24 h RH 未胜 Persistence，q90 覆盖率低于门槛，温度残差 lag-24 自相关仍高；测试期还包含单传感器极端高温段。

准确模拟成都真实番茄采收还差的关键证据：至少一个完整独立生长季的逐批采收日期、鲜重、等级和淘汰量；两套遮阳通风良好的室内温湿度传感器；执行器位置反馈；灌溉量与基质含水率；明确的品种、密度、定植、修剪和病害记录。没有这些数据，产量只能写成“仿真预测”。
