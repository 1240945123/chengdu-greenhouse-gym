# 玻璃温室实验绘图工作流（可复用完整流程）

> 目标：把「原始数据 → 逐时数据集 → 环境/训练 → 评估 → 可视化 → 汇总」全链路标准化，
> 任何一次新实验（换算法 / 换 reward / 换场景）都能按同一套流程产出**风格统一、口径一致**的图表。
>
> 适用仓库：`chengdu-greenhouse-gym`；工作目录：仓库根目录。

---

## 0. 全流程总览（7 个阶段）

```
①原始数据 ─► ②数据准备 ─► ③环境配置 ─► ④训练 ─► ⑤评估 ─► ⑥绘图 ─► ⑦汇总
 (xls/csv)   (逐时对齐)   (glass_env)  (RL)    (json)   (png)   (md)
                                     └──────────┴────────┘
                                     依赖：③ 的配置决定 ④⑤ 的口径
                                     ⑥ 的图能否横比，取决于 ③⑤ 是否统一
```

**核心原则**：**一次实验只改一个变量**（reward / obs / 算法 / 场景），
其余配置冻结 → 绘图阶段才能做「受控对比」。

## 1. 阶段① 原始数据（数据源清单）

| 数据 | 来源 | 格式 | 用途 |
|---|---|---|---|
| 执行器操作日志 | `玻璃温室数据库信息/控制器数据/43~51*.xls`（9 个文件）| 事件型 xls | 人工对照组动作 |
| 室内传感器 | SQL 备份 / 采集日志 | 逐时记录 | 温度标定、真值校验 |
| 室外天气 | 气象站 / ERA5 | 逐时记录 | 环境驱动 |
| 温室建设参数 | `0907…温室建设参数.xls` | 静态表 | 结构标定（遮阳率 75% 等）|
| 作物实测 | `2026郫都基地番茄测量数据.xlsx` | 取样表 | 作物参数标定（3 个时间点）|

**关键参数/注意事项**
- 郫都基地 = GH63 玻璃温室，**192 m²**，9 执行器，**无锅炉**；
- 建设参数里 `外遮阳 = 75% 黑色遮阳网`（透光 25%）——这是标定遮阳透光率的依据；
- 数据实际只到 **5/19**（作物实测），6-7 月无实测 → 论文需声明作物标定边界。

## 2. 阶段② 数据准备（对齐与清洗）

### 2.1 逐时数据集构建

| 项 | 内容 |
|---|---|
| **输入** | 室内传感器 + 室外天气（原始）|
| **处理** | 时间戳对齐 → 1h 重采样 → 缺失处理 → 质量标记 |
| **脚本** | `processing/build_chengdu_dataset.py`、`chengdu_sensor_stream.py`、`chengdu_sensor_quality.py` |
| **输出** | `data/processed/chengdu_agri/greenhouse_001/aligned/greenhouse_1h.csv` |
| **关键列** | `timestamp, air_temperature, outdoor_air_temperature, outdoor_relative_humidity, global_radiation, co2, …` |

### 2.2 人工档位序列构建（人工对照组的前提）

| 项 | 内容 |
|---|---|
| **输入** | 9 个执行器事件日志 xls + `greenhouse_1h.csv` 时间轴 |
| **处理** | 事件型 → 逐时档位；**前向填充**（ffill）保持状态；风机台数映射 `{0:0,1:1,2:2,4:3}` |
| **脚本** | `experiments/archive/build_actuator_states.py` |
| **输出** | `results/chengdu_agri_greenhouse_001/real_greenhouse/aligned_actuator_states.csv` |
| **关键列** | `shade_cloth, top_insulation, side_insulation, roof_vent, grow_lamp, co2_gen, pad_fan, pad_pump, pad_curtain` |

**注意事项**
- 人工日志的风机是**真实台数**（0/1/2/4），必须映射到动作空间 4 档（0-3），否则档位越界；
- 前向填充必须**先按时间戳排序**，否则状态错位（曾因此产生「人工均温 39.4°C」的假结果）；
- 用 `load_human_actions()`（定义在 `full_season_benchmark_v3.py`）统一读取，避免各处重复实现。

## 3. 阶段③ 环境配置（决定所有下游口径）

**唯一入口**：`experiments/controllers/glass_rl/glass_env.py` → `GlassGreenhouseEnv`

### 3.1 物理结构标定（`self.params[...]` 覆盖）

| 参数 | 值 | 含义 | 依据 |
|---|---|---|---|
| `p[68]/p[69]` | 0.85 | 玻璃 NIR/PAR 透光率 | 玻璃实际（原塑料棚值 0.57）|
| `p[89]/p[90]` | 0.25 | 外遮阳网 NIR/PAR 透光率 | 建设参数「75% 遮阳网」|
| `p[209]` | **0.42** | `solar_gain_scale` 辐射增益 | 生长季逐日峰值标定（原 0.91 误拟合清棚异常值）|
| `p[210]` | 0.5 | `ua_scale` 围护传热 | 物理标定 |
| `h_air_canopy` | `2·5·3·area` | 冠层对流系数 | 修冠层过热 bug |
| `SCREEN_LONGWAVE_SAVING` | 0.6（顶）/0.3（四周）| 保温幕长波反射遮蔽率 | 修保温幕失效 bug |

### 3.2 作物参数标定

| 参数 | 值 | 含义 |
|---|---|---|
| `p[137]` | 0.385×**1.7** | 量子效率 |
| `p[152]` | 3.47e-7×**0.5** | 叶维持呼吸 |
| `p[154]` | 0.328×**1.15** | 果实分配率 |
| `p[156]` | 0.074×**2.0** | 茎分配率 |

> 标定误差：茎叶果 **8.2%**（对齐 3/30、4/27、5/19 三个实测点）。

### 3.3 环境构造参数（`__init__` 可调项，**绘图口径由它决定**）

| 参数 | 默认 | 作用 | 影响哪张图 |
|---|---|---|---|
| `episode_days` | 40 | episode 长度 | 训练；评估用 102 |
| `day_indices` | [0,20,40,60,80] | 训练起始日（覆盖 4-7 月）| 训练 |
| `start_day_index` | 0 | 评估起始日（0=4/1）| 全季图 |
| `crop_start` | "seedling" | 作物起点 | 果实曲线 |
| `disable_supplements` | True | 禁用补光/CO2 | 控制热图 |
| `cooling_mode` | "overheat" | 降温奖励模式 | 训练 |
| `humidity_weight` | 2.0 | 湿度惩罚权重 | 舒适率 |
| `screen_shade_weight` | 0.5 | 白天顶保温挡光惩罚 | 控制热图 |
| `obs_include_outdoor` | True | obs 加室外温（7→8 维）| 训练 |
| `comfort_weight` | 0.3（v7/v4）| 舒适带内**正**奖励 | 舒适率图 |
| `smooth_weight` | 0.1（v7/v4）| 动作平滑惩罚（抑制档位抖动）| 控制曲线 |

**注意事项**
- ⚠️ **训练与评估必须用同一套环境参数**，否则模型「作弊」（旧模型在新环境评估会失真）；
- ⚠️ `obs_include_outdoor` 一旦改变，**obs 维度变**，旧模型无法加载（7 维 vs 8 维）；
- 统一评估口径常量建议集中定义（见 `eval_final_comparison.py` 的 `ENV_KW`）。

## 4. 阶段④ 训练（产出模型 + 训练曲线）

| 项 | 内容 |
|---|---|
| **输入** | ③ 的环境配置 + 训练脚本 |
| **脚本** | `train_ppo_optimized.py`（PPO）、`train_sac_final.py`（SAC）、`train_all_algorithms_fullseason.py`（8 算法）、`continue_train_ppo.py`（续训）|
| **输出** | `model.zip`、`checkpoint_XXXXXXX.zip`、**`training_curve.csv`**、`train_meta.json`、`tb_log/` |
| **依赖** | 无（起点）|

### 4.1 训练曲线采集（关键环节，易踩坑）

| 算法类型 | 回调钩子 | 指标 key |
|---|---|---|
| On-policy（PPO/TRPO/A2C）| `_on_rollout_end` + `ep_info_buffer` 算 `ep_rew_mean` | `train/policy_gradient_loss`、`value_loss`、`entropy_loss`、`approx_kl`、`clip_fraction` |
| Off-policy（SAC/DDPG/TD3/DQN）| `_on_step` 每 N 步采样 | `actor_loss`、`critic_loss`、`ent_coef` |

**⚠️ 三个必踩坑（已在脚本修复，复用时直接照抄）**
1. **`ep_rew_mean` 采不到**：SB3 在 rollout 结束时才 record，`on_step` 型回调采样不到 → 必须用 `_on_rollout_end` + `ep_info_buffer` 手动算 mean；
2. **CSV 表头用「第一行 keys」会崩**：`n_steps` 大的算法（PPO 2048）第一次梯度更新晚于第一个记录点，早期行缺 `train/*` 字段 → 必须用**固定完整字段列表** + `extrasaction="ignore"`；
3. **正确 key 是 `train/policy_gradient_loss`**（不是 `policy_loss`）。

### 4.2 超参数（PPO，受控对比时冻结）

`lr=3e-4, n_steps=2048, batch_size=128, n_epochs=10, gamma=0.99, gae_lambda=0.95,
clip_range=0.2, ent_coef=0.01, vf_coef=0.5, max_grad_norm=0.5`

**注意事项**
- 训练步数**不是越多越好**：reward 曲线斜率趋 0 即甜点（本任务 60 万步）；
  加长到 120 万步反而果实 -21%（策略漂移）——**以曲线斜率 + 物理指标交叉判断收敛**；
- 训练用 40 天随机片段（5 个起始日），评估才用完整 102 天。

## 5. 阶段⑤ 评估（产出指标 JSON）

| 脚本 | 评估对象 | 输出 |
|---|---|---|
| `eval_ppo_final.py` | 单个模型（可 `--with-human`）| 控制台 + 逐时轨迹 |
| `eval_final_comparison.py` | PPO vs SAC vs 人工 | `final_comparison_ppo_sac_human.json` |
| `eval_four_way.py` | PPO vs SAC vs 规则 vs 固定基准 | `final_comparison_four_way.json` |
| `eval_mpc_pid.py` | 经典控制器组（baseline/rule/pid/mpc）| `final_comparison_classical.json` |
| `plot_four_way_full.py` | 四者完整图集（指标/状态/控制/训练）| `rl/figures_four_way/` 8 图 |
| `plot_optimization_and_core.py` | 优化前后 + 核心四强（含 MPC/PID）| `rl/figures_optimization/` |
| `benchmark_all_fullseason.py` | 全策略（含经典控制）| `benchmark_fullseason_d0_102.json` |

### 5.1 统一指标口径（**所有图必须一致**）

| 指标 | 公式 |
|---|---|
| **舒适率** | 温湿联合达标小时占比：白天 T∈[20,28] & RH∈[60,85]；夜间 T∈[16,24] & RH∈[60,85] |
| **均温 / 最高温** | 102 天室内空气温度 mean / max |
| **果实 kg/m²** | `(果末 mg/m² − 果初) × 1e-6 ÷ 0.081`（0.081 = 番茄干物质比）|
| **湿度超标率** | 昼/夜 RH>85% 小时占比 |
| **分月舒适率** | 按天分箱 `[-1,30,61,91,102]` → 4/5/6/7 月 |

**注意事项**
- 果实干重→鲜重换算 `÷0.081`、`g/株 ↔ mg/m²` 换算 `×2710`（密度 2.71 株/m²）——**全流程统一**；
- 分月边界数组长度必须 ≤ 数据长度（曾因 `103×24 > 2448` 越界报错）。

## 6. 阶段⑥ 绘图（四类图，按用途分组）

### A. 训练过程图 —— `plot_training_curve.py`

| 项 | 内容 |
|---|---|

| **可调项** | 平滑窗口 `w`、CSV 路径（改 `CSV` 常量）|

### B. 温室环境状态图 —— `plot_env_trajectory.py`

| 项 | 内容 |
|---|---|
| **输入** | 训练好的 model + 环境（逐时 rollout）|
| **处理** | 逐时 → 逐日聚合（均值 + 最高/最低带）|
| **输出** | `env_temperature.png`、`env_humidity.png`、`env_co2.png`、`env_control_actions.png`（9×102 热图）|
| **可调项** | `OUT` 目录、执行器名 `ACT_NAMES` |

> 控制热图是**最有信息量**的一张：直接展示 RL 学到的策略（如「夏季收外遮阳、全力湿帘」）。

### C. 策略对比图（三类）

| 脚本 | 场景 | 输出 |

| `eval_four_way.py` | 四者对比（PPO/SAC/规则/基准）| 6 子图指标 + 分月舒适率 |
| `plot_ppo_final.py` | 单模型 vs 人工 | 温度 / 果实 / 分月舒适率 |

### D. 优化消融图 —— `plot_ab_comparison.py`

| 项 | 内容 |
|---|---|
| **输入** | 两个版本的 `training_curve.csv` + 指标 JSON |
| **输出** | `ab_reward_curve.png`（收敛对比）、`ab_metrics.png`（指标分组柱状）|
| **用途** | 验证单项优化（如 reward 改动）的净效果 |

### 6.1 全局绘图规范（**必须遵守，否则图风格不统一**）

```python

plt.rcParams["font.sans-serif"] = ["Microsoft YaHei", "SimHei", "sans-serif"]  # 中文

```

| 规范 | 值 |
|---|---|
| 配色 | 人工 `#c0392b`（红）、RL `#2c6fbb`（蓝）、规则 `#27ae60`、基准 `#95a5a6`；多算法用 `plotting.COLORS`（colorblind-safe）|
| dpi | 标准化图 300；快速对比图 130 |
| 单位 | 温度 °C、湿度 %、reward 无量纲、果实 kg/m² |
| 坐标范围 | 同类图固定范围便于横比（分月舒适率 y 轴 0-75 等）|
| 输出目录 | 按实验命名（`rl/<exp_name>/figures/`）|

**注意事项**
- ⚠️ CO₂ 下标符号在部分字体下不渲染 → 用 ASCII「CO2」；
- ⚠️ `sys.path.insert(0, ".")` + `sys.path.insert(0, "experiments/controllers/glass_rl")` 是脚本运行前提；

## 8. 依赖关系与执行顺序（DAG）

```
① 原始数据
   │
   ▼
② greenhouse_1h.csv ──┐
   aligned_actuator_states.csv
   │                   │
   ▼                   │
③ glass_env.py 配置 ◄──┘   ← 物理 + 作物标定 + reward 配置（口径源头）
   │
   ├──────────► ④ 训练 ──► model.zip + training_curve.csv
   │                          │            │
   │                          ▼            ▼
   │                    ⑤ 评估(json)   [A 训练图]
   │                          │
   │                          ▼
   └──────────────────► ⑥ 绘图 [B 环境图 / C 对比图 / D 消融图]
                              │
                              ▼
                          ⑦ 汇总(md)
```

**硬依赖**：
- ⑥-A（训练图）只依赖 ④ 的 `training_curve.csv`；
- ⑥-B/C（环境图/对比图）依赖 ④ 的 model **且** ③ 的环境参数（必须匹配训练时的配置）；
- ⑤ → ⑥-C/D 必须有 JSON，否则对比图无数据；
- **改 ③ 的任何参数 ⇒ ④⑤⑥ 全部重跑**。

## 9. 快速复用清单（新实验 Checklist）

```
□ 1. 确认数据就绪：greenhouse_1h.csv + aligned_actuator_states.csv
□ 2. 改 glass_env.py 配置（只改一个变量！），记录改动
□ 3. 训练：train_<algo>_final.py → 检查 training_curve.csv 非空
□ 4. 确认收敛：reward 斜率趋 0 + loss 稳定（不过度训练）
□ 5. 评估：eval_*.py → 得到指标 JSON
□ 6. 绘图：plot_training_curve / plot_env_trajectory / plot_<对比> / plot_ab_comparison
□ 7. 汇总：summarize_results.py → algorithm_comparison.md
□ 8. 归档：图入 rl/<exp>/figures/，脚本入 experiments/controllers/glass_rl/
□ 9. 同步：结论性 md/json/png 用 git add -f（results/ 被 gitignore）
```

## 10. 常见坑位速查（本仓库实测踩过）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 训练曲线 `ep_rew_mean` 全空 | SB3 在 rollout 结束才 record | 用 `_on_rollout_end` + `ep_info_buffer` |
| 2 | CSV 写入 `ValueError` | 表头用第一行 keys，早期行缺字段 | 固定完整字段列表 + `extrasaction="ignore"` |
| 3 | human 均温虚高 39°C | 闭包 `[i]` 每次新建、状态不持久 | 闭包用可变计数器 `state=[0]` |
| 4 | 分月舒适率数组越界 | `103×24 > 2448` | 边界数组截断到数据长度 |
| 5 | 中文变方块 | 未设字体 | `font.sans-serif = Microsoft YaHei` |
| 6 | 果实量级差 100× | 干重/鲜重、g/株↔kg/m² 换算 | 统一 `÷0.081`、`×2710` |
| 7 | 旧模型评估失真 | obs 维度 / 环境参数变了 | 评估环境必须匹配训练配置 |
| 8 | 图无法横比 | 各脚本 dpi/配色/范围不一 | 统一到本文 §6.1 规范 |
