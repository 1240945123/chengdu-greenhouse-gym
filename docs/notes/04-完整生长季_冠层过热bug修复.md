# 完整生长季 · 冠层过热 bug 修复与作物模型机制改造

> 日期：2026-09-10
> 关联：方案 A（完整标定）→ 继续深挖机制
> 结论：叶量饿死的**根因不是作物参数失配，而是 GlassGreenhouse 物理模型的冠层过热 bug**。

---

## 1. 症状回顾

覆盖完整生长季（4/1 定植起）时，作物模型在 4 月/7 月系统性失效：
- 幼苗起点（叶 5842/茎 7323/果 0）跑 30 天：叶 5842 → 670，饿死。
- GH2024 实测起点（叶 14750/茎 14250/果 500）跑 57 天：叶饿死到 829（实测应涨到 69500）、果 3077（实测应 229250）。
- 此前单参数调整全部无效（Jmax×5、量子效率×3、p[138]×300、透光 0.85、温度门 28、cBuf 0~15000）。

## 2. 根因：冠层过热（物理 bug，非作物参数）

逐时通量诊断发现三个连锁症状，全部指向**冠层温度 tCan 冲到 50~66°C**（空气才 25°C）：

| 症状 | 机制 | 后果 |
|---|---|---|
| 正午净光合 = 0 | 补偿点 gamma 随温度指数上升，66°C 时 gamma≈342 ppm > 气孔 CO2≈281 ppm | 光合归零 |
| 生长门 hTCan24 关闭 | tCan24 > p[159]=24.5°C，logistic 带通门把分配压到 0 | 叶/茎不生长 |
| 维持呼吸翻倍 | Q10=2^(0.1·(tCan24−25))，高温使呼吸×2 | 叶被呼吸吃掉 |

**为什么冠层会过热**：GlassGreenhouse 冠层热平衡
```
dxdt[4] = (solar_canopy + h_air_canopy·(t_air − t_can) − latent_heat_loss) / c_canopy
```
把 **37% 太阳辐射固定打到冠层**（`solar_canopy = 0.37·solar_total`），但对流系数 `h_air_canopy = 300 W/K` **比真实低约 19 倍**。GreenLight 原版全冠层对流 = `2·alfaLeafAir·LAI·area = 2·5·3·192 = 5760 W/K`。300 只相当于 LAI 0.16 的幼苗对流，却配了满冠层的太阳吸收 → 稳态冠层-空气温差达 39°C。

> 注意：ChengduPhysics V4/V5 用 GreenLight 原版辐射模型（冠层吸收/对流/热容均随 LAI），**没有**这个 bug。此 bug 是 GlassGreenhouse 独立改造时简化引入的。

## 3. 修复（4 处，均为机制级）

| # | 文件 | 改动 | 原理 |
|---|---|---|---|
| 1 | `glassgym/models/GlassGreenhouse/ode.py` | `h_air_canopy` 300 → `2·5·3·area`=5760 | 冠层对流对齐 GreenLight 满冠层值，冠层温贴近空气温。**不改变空气温**（稳态 `h·(tCan−tAir)=solar_canopy−latent` 守恒） |
| 2 | `glassgym/models/GreenLight/aux_states.py` | 分配门 a[205] 由硬阈值 logistic 改为 Michaelis-Menten 平滑门 `cBuf/(cBuf+0.5·cBufMax)` | 幼苗日光合 <1 g/m² 时，原硬阈值永远关闭分配→叶饿死；平滑门让分配随缓冲池连续缩放（源限制）。半饱和点取 cBufMax/2=10000，让缓冲池积累多天储备，阴雨天不饿死叶（K=1000 时果仅 57831，K=10000 时 147643，×2.6） |
| 3 | `experiments/controllers/glass_rl/glass_env.py` | 幼苗起点 `x[26]=0`（发育积温从定植起算），`cBuf=2000` | 原 seedling 沿用成熟发育量 3097，果实汇一开就与叶抢碳 |
| 4 | `glassgym/models/GreenLight/aux_states.py` | 果实分配 a[208] 额外 ×`canopy_frac=min(1,LAI/laiMax)` | 果实汇随冠层发育同步增强（营养生长优先→冠层闭合后强结果），避免果实抢光光合饿死叶 |
| 5 | `experiments/controllers/glass_rl/glass_env.py` | 外遮阳透光率 p[89]=p[90] 0.01→**0.25** | **第二个关键 bug**：默认 0.01 是遮光幕（催花黑幕）透光率，但 GH63 外遮阳是「75% 黑色外遮阳网」（建设参数），透光 25%。原值使白天一开遮阳 PAR 被挡 99%，光合从 23 g/m²/天崩到 3-6 g。0.25 与能量模型 `(1−0.75·u_bl_scr)` 一致 |

> 第 2/4 处改动在共享的 GreenLight aux_states 中，对 ChengduPhysics V1-V4 也生效；但 V4/V5 的作物是成熟株（LAI≈2.5、缓冲池高），影响仅 ~15%（果实分配 ×0.84）。**V4/V5 的温控结论不受影响**（作物不驱动温度），仅产量侧需重估。第 5 处仅改 GlassGreenhouse 环境，不动 default_params（V4/V5 的黑幕语义保留）。

## 5. 遗留工作（按优先级）

1. **【中】光合绝对量精标定**：果实 148 g/m² 达 GH2024 实测 229 g 的 **65%**，叶 98% 达标。剩余 ~1.5x 缺口属精标定范畴（且 GH2024 为不同温室/年份的松对比）。可微调遮阳网透光率（真实 75% 遮阳网，0.25 已是建设参数值）、量子效率、气孔导度等进一步逼近。
2. **【中】全季 RL 重训**：作物模型已改，需用新的 seedling 起点重训 RL，评估完整 102 天窗口。
3. **【中】回填旧 benchmark**：冠层 bug + 遮阳 bug 影响此前的作物/产量结果（温控结论不受影响），需重新评估。
4. **【低】V4/V5 遮阳语义确认**：V4/V5 若遮阳也是遮阳网（非黑幕），需同样把 p[89]/p[90] 改 0.25。
