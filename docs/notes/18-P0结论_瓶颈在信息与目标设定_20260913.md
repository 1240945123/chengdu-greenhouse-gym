# 18 - P0 结论：瓶颈在「信息与目标设定」，不在算法复杂度（2026-09-13）

> 汇总四条 P0 算法候选（动作掩码 / off-policy 补强 / 蒸馏 / 前瞻前沿）在同一冻结协议下的
> 完整结论，并给出三条相互印证的证据链。这是 `13-P0决策` 之后、转入论文写作前的**实验收口**。

## 0. 一句话结论

**在郫都玻璃温室基准上，继续增加算法复杂度（多智能体、掩码、循环、蒸馏、更深前瞻）都
没有带来舒适的实质提升；真正的杠杆是"给控制器更多信息"（观测）与"把目标函数设对"（奖励/口径），
而不是"换更强的算法"。**

三条证据链互证：

| 方向 | 操作 | 结果 | 判读 |
|---|---|---|---|
| **减**（动作空间） | P0-1 掩码 1536→384 | 舒适 **−7.6pp**、产量 +1.09 | 精简动作**不划算** |
| **加**（观测信息） | P0-3 观测 8→23 维 | 舒适 **+16.5pp**（44.6→61.1） | 信息**是**杠杆 |
| **加**（前瞻深度） | P0-4 H=1→H=2（等候选） | 舒适 +0.2pp、延迟 ×7.3 | 看更远**无收益** |

→ 瓶颈在**信息与目标设定**，非算法复杂度。这一判断修正了此前"奖励塑形边际收益耗尽"的
旧结论（`09`/`08`），把矛头从"奖励设计"进一步指向"**观测信息不足**"。

## 1. P0-1 · 动作掩码（1536 → 384）

**做法**：禁补光/CO2 后，8 个执行器里 5 个维度恒为 0，实际有效组合仅 384。用
`SupplementMaskEnv` + `supplement_action_mask()` 静态掩码训练 `MaskablePPO`，与无掩码 `PPO v6`
单变量对照。

| 指标 | PPO v6（无掩码） | MaskablePPO（掩码384） | Δ |
|---|---:|---:|---:|
| 舒适率 % | 52.5 | 44.9 | **−7.6** |
| 果实 kg/m² | 7.28 | **8.37** | **+1.09** |
| 最高温 °C | 33.6 | 31.7 | −1.9 |
| 无效动作占比 | ~200% | 0% | 归零 |
| 决策 ms | 1.08 | 2.30 | +1.2 |

**结论**：动作掩码**不是免费午餐**，而是**Pareto 重排**——它把策略从"拼舒适率"推向"拼产量"
（无效动作归零后，动作更"敢用"、产量更高、最坏温度更低，但舒适窗口的精细调节变差）。
在"舒适率优先"的目标下，掩码无净收益。

## 2. P0-2 · off-policy 家族补强（TQC / CrossQ）

**动机**：off-policy 原来只有 SAC，且是短板（35.9%、最高温 41.9°C、有 10% 过热日）。

| 指标 | SAC v3 | TQC | **CrossQ**（450k） |
|---|---:|---:|---:|
| 舒适率 % | 35.9 | 38.9 | **47.4** |
| 果实 kg/m² | 6.58 | 6.93 | **8.59（全表最高）** |
| 最高温 °C | 41.9 | 33.1 | **31.6（全表最低）** |
| 无过热日 % | 90.2 | 100 | 100 |
| reward | −79 | +80 | +208 |

**结论**：
1. **TQC 修好了 SAC 的安全短板**——最高温 41.9→33.1°C、无过热日 90→100%、reward 由负转正。
2. **CrossQ 是 off-policy 侧的赢家**：以 450k 步（75% 预算）同时取得**最高产量 8.59** 与
   **最低最坏温度 31.6°C**，舒适率 47.4% 也超过 SAC/TQC。其 BatchNorm 去目标网络的机制
   在本环境样本效率突出。代价：产量优势来自"春季高舒适"（4月 73.8%），6-7 月舒适率骤降
   （25.6 / 9.1），即**用春季换全季产量**。
3. off-policy 整体仍**低于 on-policy 离散（TRPO 56.0）**——连续动作空间在该离散执行器上
   并非优势（DQN 16.7、DDPG/TD3 14.6 的塌缩见 `17` §4.3）。

## 3. P0-3 · DAgger 蒸馏 MPC（v1 失败 → v2 归因 → 信息赤字）

**动机**：把"高舒适但慢"的 MPC（67.4%）蒸馏成"快"的小网络。

### v1：逐维准确率很高，全季却崩
- 逐维准确率 **94.7%**（BC + 1 轮 DAgger），但整季舒适率仅 **42.5%**，
  最终评估 **44.6%**（远低于教师 67.4%）。
- **归因**：逐维准确率高 ≠ 轨迹正确。9 维动作的**联合准确率**只有 ~74%，
  且误差在 102 天闭环中**复合放大**——单步小偏差累积成轨迹漂移。

### v2：只加信息（观测 8 → 23 维），不换算法
- 学生输入扩到 **23 维** = obs(8) + 当前天气(4) + 时刻编码(2) + **上一动作(9)**。
- 结果：舒适率 **44.6 → 61.1%（+16.5pp）**；让专家接管关键维度（顶窗/风机）可达 **64.4%**。

| 学生 | 输入维 | 舒适率 % |
|---|---:|---:|
| v1（原） | 8 | 44.6 |
| v2（+天气/时刻/上一动作） | 23 | **61.1** |
| v2 + 专家接管[顶窗,风机] | 23 | 64.4 |
| v2 + 专家接管[外遮阳] | 23 | 61.8 |
| 教师 MPC | — | 67.4 |

**结论**：蒸馏失败**不是网络容量问题，而是观测信息赤字**（缺未来天气、缺上一动作导致的
时序不可辨）。**同一批网络、同一蒸馏流程，仅把输入从 8 维扩到 23 维就回收了 16.5pp**
——这是"信息 > 算法"最直接的单变量证据。

## 4. P0-4 · H 步前瞻前沿（一步前瞻已近最优）

**做法**：用**环境 reward 本身**作为目标（与 RL 同源，消除原 MPC 自定义评分的口径差），
以 H 为唯一自变量，在**等算力 / 等候选数**两种约束下画成本-性能前沿。

| 约束 | H | 舒适率 % | 果实 | 决策 ms | 每决策推演数 |
|---|---:|---:|---:|---:|---:|
| **等算力**（预算 192） | 1 | 67.9 | 7.15 | 88.9 | 100 |
| | 2 | 66.4 | 6.99 | 301.0 | 384 |
| **等候选数**（N=192） | 2 | 68.1 | 7.15 | **645.3** | 768 |

**结论**：
- **等算力下 H 越大越差**（H=2 66.4 < H=1 67.9）——更深前瞻被候选数骤减抵消。
- **等候选数下 H=2 只比 H=1 高 +0.2pp（68.1 vs 67.9），却慢 7.3 倍**（645 vs 89ms），
  推演数 7.6 倍（768 vs 100）。
- → **一步前瞻（H=1）已近最优**。环境的一步 reward 已充分编码未来代价（`humidity_weight=2.0`
  把"现在开湿帘、几小时后湿度代价"提前惩罚），无需显式多看几步。

## 5. 综合结论与论文落点

### 5.1 实验级结论

1. **舒适率天花板由"模型预测"把持**（前瞻/MPC 67-68%），RL 侧最好的是 **TRPO 56.0%**
   与 PPO v9 54.8%（`17` §2）。
2. **RL 的价值是成本**：以 ~1ms 的推理逼近 ~80ms 的 MPC，成本低 1-2 个数量级——
   这才是 RL 在温室控制里的立论点，而非"超过 MPC"。
3. **瓶颈在信息与目标设定**：三条 P0 互证（§0 表）——动作精简不划算、观测信息是杠杆、
   一步前瞻已足够。**所有复杂化尝试（多智能体 47.0 / 掩码 44.9 / 循环 45.5 / 蒸馏 44.6）
   都没超过简单的前瞻搜索与 TRPO。**

### 5.2 对论文的落点

- **第 5 章主表**用 `17` §2（20 策略）与 §3（分月）；**核心论点图**用 `algorithm_matrix.png` ③
  （成本-性能前沿）。
- **7 月高温（全表最高仅 25.0%）** 作为"物理调控上限"的讨论点——提示真实部署需
  结合通风/湿帘能力上限，而非只换算法。
- **"信息 > 算法"** 作为方法论贡献：蒸馏单变量实验（8→23 维，+16.5pp）是干净证据。
