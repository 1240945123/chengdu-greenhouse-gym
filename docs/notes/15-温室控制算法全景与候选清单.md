# 15 - 温室控制算法全景与候选清单

> 用途：论文第 2 章「相关工作」的方法族骨架 + 第 7 章「未来工作」的候选池。
> 边界：本文档区分「**已实现**」与「**候选**」，候选不等于要做；末尾给出实现 vs 仅讨论的分工建议。

## 0. 一个必须先澄清的事实：现有「MPC」是一步前瞻搜索

读 `experiments/controllers/glass_rl/classical_controllers.py` 的实现：

```
GlassMPC：
  候选集 = 遮阳{0,1} × 顶窗{0,1,2} × 风机{0,1,2,3} × 水泵{0,1} × 卷膜{0,1} = 96 组合
          （低温时动态附加保温{0,1}² → 最多 384）
  评分   = 预测一步后的 (产量增益 − 温度惩罚 − 湿度惩罚 − 能耗)
  选优   = 枚举取评分最高者
```

即：**H=1 的滚动时域枚举搜索（one-step lookahead exhaustive search）**，而非求解多步优化问题的 MPC。这带来三条必须在论文里如实声明的结论：

| 项 | 说明 |
|---|---|
| **命名** | 严格应称「一步前瞻模型搜索 / 近似 MPC」，而非 standard MPC。论文中建议写为 *one-step receding-horizon model-based search*，并注明其为 MPC 的退化情形 |
| **性能来源** | 它的评分函数与评价指标（舒适率/产量）**同构**——等于「直接优化评分标准」；而 RL 只能从 reward 里**学**指标代理。所以「MPC 67.4% vs PPO 52.5%」必须加此限定，否则对 RL 不公平 |
| **成本来源** | 76 ms/决策 = 96~384 次候选积分；延迟随候选数线性增长 |

**这条反而制造了一个高价值实验**：把 H 从 1 扩到 4/8（或改采样式），可画出「**前瞻步数 H → 舒适率 → 决策延迟**」的曲线，直接量化 MPC 的成本-性能前沿，与 RL 的「1 ms 定点」形成对照。这比再训一个 RL 算法对论文的贡献大得多。

## 1. 五层全景

温室控制不是一个「选哪个 RL」的问题，算法分属五层，各层解决不同问题：

| 层 | 回答的问题 | 时间尺度 | 本项目状态 |
|---|---|---|---|
| **L1 设定点层**（supervisory） | 目标温湿度该是多少 | 天–周 | 部分（规则内含温度分层） |
| **L2 调节层**（regulatory） | 如何跟踪设定点 | 秒–分 | 部分（PID） |
| **L3 预测层**（predictive） | 未来天气下如何提前动作 | 时–天 | 部分（一步前瞻搜索） |
| **L4 学习层**（learning） | 能否从交互中自己学会 | — | 充分（8 算法 + IPPO） |
| **混合层**（hybrid） | 学习与控制如何互补 | — | 起步（残差 RL） |

## 3. 候选清单（按层）

> 「适配度」= 与本项目已有代码/模型/数据的复用程度；「成本」= 实现+训练/评估工作量。

### L1 设定点层

| 算法 | 思路 | 适配度 | 成本 | 价值 |
|---|---|---|---|---|
| **作物模型最优设定点** | 用 Vanthoor 作物模型反解最优温湿度轨迹（离线优化），再交给 L2/L3 跟踪 | 高（模型已有） | 中 | ⭐⭐⭐ 与 RL「端到端」形成「分层 vs 端到端」对照 |
| **贝叶斯优化调参** | 对 reward 权重（yield/temp/humidity）做 BO 搜索，替代手工试 | 高 | 低 | ⭐⭐ 直接回应「comfort_bonus 三轮无效」——用系统化搜索替代试错 |
| 极端天气设定点保护 | 高温预警下切安全设定点 | 高 | 低 | ⭐⭐ 工程落地性 |

### L2 调节层

| 算法 | 思路 | 适配度 | 成本 | 价值 |
|---|---|---|---|---|
| **增益调度 PID** | 按工作点/时段切 PID 参数（现有 PID 33.4% 偏弱的主因） | 高 | 低 | ⭐⭐⭐ 把 PID 基线做扎实，堵住「PID 太弱所以 RL 赢得不公平」的评审质疑 |
| **ADRC 自抗扰** | 扩张状态观测器补偿未建模扰动 | 中 | 低 | ⭐⭐ 对模型误差鲁棒，可与参数敏感性结论呼应 |
| **模糊控制** | 语言规则 + 隶属度 | 高 | 低 | ⭐⭐ 中文温室控制文献主流方法，相关工作必覆盖 |
| LQR / LQG | 线性最优状态反馈 | 中 | 低 | ⭐ 需线性化，对本非线性对象一般 |
| 迭代学习控制（ILC） | 利用重复日周期修正 | 中 | 中 | ⭐ 日周期性强，理论上契合，实现偏小众 |

### L3 预测层（MPC 族）

| 算法 | 思路 | 适配度 | 成本 | 价值 |
|---|---|---|---|---|
| **MPPI / CEM 采样 MPC** | 采样 N 条动作序列、按模型滚动 H 步、按代价加权 | **极高**（直接复用现有模型与评分函数） | **低** | ⭐⭐⭐ **P0**：把 H=1 穷举升级为 H≥8 采样优化，一次性拿到「性能-成本前沿曲线」 |
| **EMPC 经济型 MPC** | 目标改为直接优化经济指标（产量−能耗），而非跟踪舒适带 | 高（评分函数改一行） | 低 | ⭐⭐⭐ 与 RL「最大化 reward」**同构对照**：同模型、同目标、不同求解方式 |
| **NMPC** | 非线性 MPC + 求解器（IPOPT/ACADO） | 中 | 中–高 | ⭐⭐ 理论正确但求解慢，用于「性能上界」参考 |
| 随机 / 管 MPC（tube） | 显式建模天气不确定性 | 中 | 中 | ⭐⭐ 有鲁棒性论述价值，但需天气集合预报 |
| 天气预报前馈 MPC | LSTM/Transformer 预报辐射→MPC 提前动作 | 中 | 中–高 | ⭐⭐ 直击「MPC/RL 都只能反应式」的痛点 |

### L4 学习层（我们还没试的）

| 算法 | 思路 | 适配度 | 成本 | 价值 |
|---|---|---|---|---|
| **MaskablePPO**（动作掩码） | 对无效动作位（补光/CO₂）做掩码，1536→384 | **极高**（sb3-contrib 已装） | **极低** | ⭐⭐⭐ **P0**：一次训练同时回答「动作空间精简」与「探索预算浪费」两个遗留问题 |
| **TQC** | SAC + 分布式截断分位数 critic + 优先回放 | **极高**（sb3-contrib 已装） | **极低** | ⭐⭐⭐ **P0**：补强 off-policy 家族（SAC 是我们短板） |
| **CrossQ** | 2024 新算法，BatchNorm 替代目标网络，样本效率超 SAC | 极高（已装） | 极低 | ⭐⭐⭐ **P0**：样本效率故事的最强证据 |
| **PPO-Lagrangian / CPO** | 把安全约束（如最高温≤35°C）写进约束而非惩罚 | 高 | 低–中 | ⭐⭐⭐ **P1**：对症「residual_ppo 曾因安全阈值违规被排除」；安全与产量解耦 |
| **MAPPO（CTDE）** | 集中训练 + 分散执行的多智能体 | 高（IPPO 已有） | 中 | ⭐⭐⭐ **P1**：直接对比「独立 IPPO vs 集中训练」，是现成的改进靶子 |
| ARS（增强随机搜索） | 无梯度随机搜索 | 极高（已装） | 极低 | ⭐⭐ 作为「极简基线」，证明问题难度 |
| 有模型 RL（DreamerV3 / MBPO / PlaNet / PETS） | 先学世界模型再规划 | 低（SB3 不支持，需自研） | 高 | ⭐⭐ 样本效率叙事好，但真实温室数据贵不在仿真阶段，性价比低 |
| 离线 RL（CQL / IQL / TD3+BC / BCQ） | 只用固定数据集学策略 | 中（有 102 天人工日志 + 仿真数据） | 中 | ⭐⭐ 「真实温室不能随便试错」的解法，研究价值高 |
| 决策 Transformer / 扩散策略 | 序列建模/生成式策略 | 低（数据量不足） | 中 | ⭐ 时髦但不适配小数据 + 低频决策 |
| 分层 RL（options / HAC） | 高层选目标、低层执行 | 中 | 中 | ⭐⭐ 与 L1 设定点层天然对应 |
| 元 RL / 域随机化 / 迁移 | 跨温室、跨季快速适应 | 中（有 GH2024 新都数据） | 中 | ⭐⭐⭐ 直接服务「可迁移性」这一论文卖点 |

### 混合层（最贴合本项目「两论并重」）

| 算法 | 思路 | 适配度 | 成本 | 价值 |
|---|---|---|---|---|
| **DAgger / BC 蒸馏** | 以 MPC（67.4%）为专家，生成状态-动作对训练小网络（DAgger 迭代纠正分布漂移） | **高**（MPC 已实现） | **低** | ⭐⭐⭐ **P0 首选**：一次离线数据生成 + 监督学习，把 67.4% 的决策能力压进 1 ms 网络——**这才是「MPC 性能 + RL 成本」这句卖点的真正兑现方式**，且比在线残差训练（MPC 76 ms × 60 万步 ≈ 12 h）便宜一个量级 |
| **残差 RL** | 基线控制器 + RL 修正量 | 已实现 | — | ⭐⭐ 已验证：比基线强但未超 PPO，价值在「更快更安全」 |
| **RL 调 MPC 权重** | RL 学 MPC 的 Q/R 或目标权重，而非直接学动作 | 中 | 中 | ⭐⭐ 小动作空间、易训练，是「RL 学什么」的另一种答案 |
| 可微 MPC / 学习型 MPC | 用 NN 替代 MPC 内部模型，端到端可微 | 中 | 高 | ⭐⭐ 理论优雅，但对本项目（模型已知且可微）收益有限 |
| **Koopman-MPC** | 用 DMD/Koopman 算子把非线性系统提升为线性，再用线性 MPC | 中 | 中 | ⭐⭐ 近年热点，可作「数据驱动线性化」的方法论对照 |
| 安全层（shielding / CBF） | 在任意策略输出后加一层硬约束投影 | **高** | 低 | ⭐⭐⭐ **P1**：外部安全层可同时保护 RL 与 MPC，是工程落地必备，也回答「如何保证不烧苗」 |

> 下表只给**方法族分类**，具体文献需按实际检索结果逐条核实补引（勿凭记忆填标题/年份）。

| 方法族 | 典型代表（方法层面） | 在本项目的对应 |
|---|---|---|

| 层级控制 | 监督层 + 调节层两级结构 | 对应 L1+L2 分层 |
| 模型预测控制 | 跟踪型 MPC、经济型 MPC、非线性 MPC | 对应 L3（本项目仅一步前瞻） |

## 5. 推荐路线与优先级

### P0（实现成本极低，直接补齐真空 + 强化两论）

| # | 动作 | 理由 | 预期产出 |
|---|---|---|---|
| P0-1 | **MaskablePPO + 动作掩码** | sb3-contrib 已装；一次训练回答「动作空间精简」遗留项 | 掩码 vs 无掩码的样本效率对比 |
| P0-2 | **TQC + CrossQ** | 同上，替换 SAC 一行代码 | off-policy 家族补强，样本效率曲线 |
| P0-3 | **DAgger 蒸馏 MPC** | 兑现「MPC 性能 + RL 成本」的核心卖点，且离线生成数据成本低 | 蒸馏网络 vs MPC vs PPO 三方：性能/延迟对照 |
| P0-4 | **MPPI / H 步前瞻** | 复用现有模型与评分函数；顺便修正「MPC」命名 | 「前瞻步数 H → 舒适率 → 延迟」前沿曲线 |

### P1（研究价值高，成本中等）

| # | 动作 | 理由 |
|---|---|---|
| P1-1 | **MAPPO** | 现成靶子：独立 IPPO 已证「表现中等」 |
| P1-2 | **安全 RL（PPO-Lagrangian）/ 外部安全层** | 对症曾被排除的安全违规；解耦安全与产量 |
| P1-3 | **EMPC 经济型 MPC** | 同模型同目标、不同求解方式——最严格的 RL 对照 |
| P1-4 | **增益调度 PID / 模糊控制** | 把经典基线做扎实，堵评审质疑；覆盖中文文献主流方法 |

### P2（写进未来工作，不必实现）

DreamerV3/MBPO、离线 RL（CQL/IQL）、Koopman-MPC、分层 RL、元 RL/域随机化/跨棚迁移、决策 Transformer。

### 明确不做

- 为堆算法数量而扩展——已有 8 RL + 5 经典 + 多智能体 + 残差，**已满足基准类论文的评审要求**；
- 端到端大规模超参搜索（边际收益已在三轮实验中证伪）；
- 需自研框架的算法（DreamerV3 等）——投入产出比与当前时间预算不符。

## 6. 环境可用性（已核实）

```
stable_baselines3 : 2.8.0      （PPO / SAC / DDPG / TD3 / A2C / DQN / TQC? 否）
sb3_contrib       : 2.8.0      → TQC / CrossQ / MaskablePPO / ARS / QRDQN / TRPO 均可直接 import
torch             : 2.12.0+cpu （注意：CPU-only，训练时长按此估算）
```

> 这意味 **P0-1 / P0-2 / ARS 的实现成本≈0**（无需装包、无需自研），只需替换模型类与动作空间包装。
